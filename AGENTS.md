# Verbindliche Arbeitsregeln

Diese Arbeitsregeln gelten für zukünftige Entwicklungsaufträge im Repository `SolarBergler/solarprognose_1`.

1. Wenn ich eine konkrete Änderung oder Fehlerbehebung beauftrage, ist damit die vollständige technische Umsetzung einschließlich Tests und Veröffentlichung auf GitHub genehmigt.

2. Arbeite selbstständig bis zum fertigen Ergebnis. Warte nicht auf eine manuelle Codeprüfung oder einen Merge durch mich.

3. Veröffentliche erfolgreiche und getestete Änderungen direkt auf `main`, sofern die Repository-Berechtigungen dies zulassen.

4. Falls ein Pull Request notwendig ist, prüfe und merge ihn selbstständig, soweit technisch möglich und erlaubt.

5. Erhalte bestehende Funktionen. Insbesondere dürfen PV-Berechnung, Wetterdaten-Fallback, Verschattungsmodelle und automatische Archivierung nicht unbeabsichtigt verändert werden.

6. Führe angemessene Tests durch. Veröffentliche keine Änderungen, wenn wichtige Tests fehlschlagen.

7. Frage nur nach, wenn eine fachliche Entscheidung fehlt, erhebliche Risiken bestehen oder eine notwendige Berechtigung nicht vorhanden ist.

8. Führe keine zusätzlichen, nicht beauftragten Funktionen ein.

9. Berichte abschließend kurz auf Deutsch, was geändert, getestet und veröffentlicht wurde. Nenne die neue Version und den GitHub-Commit.

10. Diese Regeln gelten für ausdrücklich erteilte Entwicklungsaufträge. Ohne solchen Auftrag dürfen keine eigenständigen Änderungen vorgenommen werden.

Der Nutzer ist kein Programmierer. Er erwartet fertige, funktionierende Ergebnisse und keine technischen Freigabeaufgaben.
